## Подтверждённая ошибка первой карты

Первый exporter использовал entry→max(body) как сплошной interval. У noncontiguous function
body это захватывает чужой промежуточный код. В частности, функция 0x001322D4 имела 2 188
body bytes при bounding span 0x1E8BC; 0x00132BD8 — 1 308 bytes при span 0x1DFC0.
Первый lift создал для них C++ файлы 10 226 297 и 10 019 332 байт. MSVC завершился C1002
на backend pass (work/build-native-004.log); успешно слинкованного native exe не было.

## Исправление и проверка

Exporter теперь собирает union реальных Ghidra AddressRanges, разбивает на границах функций
и ranges, сохраняет все covered chunks и не включает holes. Это не обрезание body по размеру.
Lift validator дополнительно требует sorted/disjoint records, size=end-start, instruction
alignment и размещение в executable file-backed PT_LOAD.

- Реальная карта: 7 796 Ghidra functions → 8 212 disjoint code records; 2 169 136 covered bytes.
- Synthetic Ghidra regression: одно искусственное discontinuous body → ровно два 4-byte records,
  4-byte hole отсутствует. Evidence: work/ghidra-regression-map-001.log.
- 15 Python tests: intake, exact ELF/opt-in guards, rejection of gap-spanning/overlapping maps.
- Lift-002: exit 0, 8 212 recompiled code fragments, 0 stubs/skip/decode failures/errors.
- 1 536 warnings о косвенных переходах остаются; их наличие не скрывается.
